Cómo publicamos este sitio con Vite y GitHub Pages

20 de agosto de 2026 Infraestructura 5 min de lectura

Queríamos un sitio rápido, sin framework, con varias páginas reales y desplegado automáticamente. Esto es exactamente lo que estás viendo, y así está armado.

Multipágina de verdad, no SPA

Cada página es un index.html completo dentro de su propia carpeta. La navegación es con enlaces normales: <a href="/blog/">. No hay router en JavaScript, no hay estado que hidratar y cada URL funciona aunque el JS falle. 

index.html                  ->  /
about/index.html            ->  /about/
blog/index.html             ->  /blog/
blog/primer-post/index.html ->  /blog/primer-post/
contacto/index.html         ->  /contacto/

Vite detecta las páginas solo

El punto molesto de una app multipágina en Vite es tener que declarar cada entrada en rollupOptions.input. Lo resolvimos con un glob sobre **/index.html al cargar la configuración: 

const archivos = globSync('**/index.html', {
  cwd: root,
  exclude: (nombre) => ['node_modules', 'dist', 'public', '.git'].includes(nombre),
})

Con eso, publicar un artículo nuevo es crear una carpeta con su index.html y hacer commit. La configuración de build no se toca nunca más.

Un solo punto de entrada de JavaScript

Todos los HTML cargan /src/main.js. Ese archivo importa el CSS, lee la configuración y pinta el header y el footer compartidos dentro de <header id="nav"> y <footer id="footer">. Cambiar un link del menú es editar un archivo, no cinco.

Configuración editable sin recompilar

Hay dos tipos de configuración y conviene no confundirlos:

  • public/config.json: se sirve tal cual y se lee con fetch() al arrancar. Editarlo cambia el sitio sin volver a compilar.
  • import.meta.env.VITE_*: se incrusta en el bundle durante el build. Cambiarlo exige recompilar y redesplegar.
Nunca pongas un secreto en una variable VITE_. Todo lo que lleva ese prefijo termina en texto plano dentro de dist/, y dist/ es público.

Despliegue en cada push

El workflow de GitHub Actions se dispara con cada push a main: instala con npm ci, compila con npm run build inyectando las variables definidas en Settings → Secrets and variables → Actions, y sube dist/ como artefacto de Pages. Un segundo job publica.

El detalle del dominio propio

Como el sitio vive en jvcloud.cl y no en una subruta de github.io, la base de Vite es '/'. Y el archivo public/CNAME con el dominio adentro se copia a dist/ en cada build: si no está, GitHub Pages olvida el dominio personalizado en el siguiente despliegue.
